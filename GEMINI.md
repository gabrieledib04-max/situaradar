# Prompt di Sistema / PRD per Antigravity: Progetto "SituaRadar"## 1\. Visione del Progetto**Nome:** SituaRadar**Obiettivo:** Creare un'applicazione web/mobile-responsive che identifichi e mostri su mappa le "situa" (eventi, feste, ritrovi sociali con alta interazione umana).**Metrica Chiave:** La "situa" viene calcolata individuando zone con un'alta concentrazione di persone, ma con un **tasso di utilizzo attivo dello smartphone estremamente basso**. L'assunto base è: se c'è molta gente ma nessuno guarda il telefono, c'è una bella atmosfera e le persone stanno interagendo tra loro.## 2\. Stack Tecnologico RichiestoImplementa il progetto utilizzando il seguente stack (ottimizzato per l'ambiente di sviluppo):* **Backend:** Node.js con framework Express.* **Database:** MongoDB (per memorizzare le coordinate storiche, i log dei ping dei dispositivi e i cluster di situa).* **Frontend:** HTML, CSS, JavaScript (Vanilla o framework leggero) integrato con una libreria di mapping (es. Leaflet.js o Mapbox GL JS).* **Ambiente / Deploy:** Configurazione tramite Docker e Docker Compose per avviare db e server in container separati.## 3\. Funzionalità Core da Sviluppare### A. Integrazione Mappa e Localizzazione* Inizializza la mappa centrata di default sulla regione **Puglia** (con un focus particolare sulle zone costiere o ad alta densità di eventi).* Permetti lo zoom sia a livello locale (città) che regionale o globale.* Implementa la geolocalizzazione dell'utente (richiesta permessi HTML5 Geolocation API).### B. Rilevamento "Phone Usage" e Presenza*Poiché accedere ai dati di utilizzo di app terze di utenti non consenzienti è bloccato dai sistemi operativi (iOS/Android), progetta il sistema con questo approccio:** **L'App Client (Opt-in):** L'applicazione web o PWA richiede i permessi di localizzazione in background e traccia (tramite Page Visibility API o screen lock detection se nativa) se lo schermo è attivo o meno mentre l'app è in uso/background.* **Simulatore per MVP:** Costruisci un modulo nel backend Express che generi dei *dati mock* (mock data generator) simulando cluster di utenti sulla mappa. Il generatore deve creare sia utenti "zombie" (telefono attivo) che utenti "vibing" (telefono in tasca/schermo spento).### C. Algoritmo "Situa" (Heatmap)* Sviluppa un endpoint backend (`/api/radar`) che raggruppi le coordinate degli utenti vicini (clustering spaziale, es. raggio di 50-100 metri).* Calcola l'indice di Situa: `(Numero di utenti con schermo spento / Numero totale di utenti nel cluster) \\\\\\\* Densità`.* Se l'indice supera una certa soglia, il frontend disegnerà un "Hotspot" (Heatmap o Marker custom) colorato (es. rosso/fuoco per la situa massima, blu/freddo per le zone morte dove tutti sono al telefono).## 4\. UI/UX e Design* Tema scuro (Dark Mode) di default per un utilizzo notturno (ideale per chi cerca eventi o serate).* Interfaccia minimale: la mappa a tutto schermo, un bottone "Radar Scan" per aggiornare i dati, e un toggle per passare dalla vista "Puglia" a "Globale".* Includi un sistema di filtri: "Mostrami solo situa con più di 20 persone".## 5\. Task per Antigravity (Step di esecuzione)1. **Inizializzazione:** Genera il `package.json`, il `docker-compose.yml` (Node + MongoDB) e il `Dockerfile`.2. **Server:** Scrivi il server Express con la connessione a MongoDB e i modelli Mongoose per il tracciamento anonimo delle coordinate e dello stato del device (`isScreenOn`).3. **Mocking:** Crea uno script di seed che popoli alcune zone (es. Monopoli, Bari, o Lecce) con dei cluster finti di dispositivi per testare l'algoritmo.4. **Frontend:** Sviluppa l'`index.html` con la mappa Leaflet, il polling dei dati dal backend ogni 30 secondi e il rendering della heatmap basata sul "Situa Index".*Nota per l'AI: Inizia generando la struttura delle cartelle e i file di configurazione Docker e Node.*
